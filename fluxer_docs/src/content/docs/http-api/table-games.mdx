The [room theme](/http-api/voice-seats/#room-themes) of a guild voice channel can place game tables in its room, one for each table slot such as `T01`. The members connected to the channel play Classic Okey, 101 Okey, chess, Türk daması, Normal dama, or tavla at them. The server holds every game: it deals and rolls, checks each move against the rules, runs the turn clocks, and sends each player only what that player may see.

The routes on this page are user-only. A bot or OAuth2 bearer credential is refused with 403 `ACCESS_DENIED`. Every route needs the access [Get channel](/http-api/channels/#get-channel) needs on a guild voice channel. Opening a table, sitting down, watching, and reading also need [CONNECT](/http-api/permissions/) and a `connection_id` that passes the [voice membership](/http-api/voice-seats/#voice-membership) check.

:::note[Table games start switched off]
Table games need 3D rooms. The [Admin API](/admin-api/instance/#voice-room-configuration-object) switches both, and a client reads the state as `games` in the `voice_room` assignment of [Get experiment assignments](/http-api/experiments/#get-experiment-assignments). While games are off, every route returns 403 `FEATURE_TEMPORARILY_DISABLED`, and the server ends each open table as `canceled` with reason `disabled`.
:::

:::caution[A rack is private to its player]
A player's rack appears in that player's own responses and Dispatches alone. No response, Dispatch, or error carries another player's rack or the order of the pile, and every view a spectator receives has `rack` null. A 101 rack stays hidden after the hand ends, and only the melds laid on the table are public.

Chess, dama, and tavla hide nothing: every viewer sees the same board, and only `legal_moves` is for the player to move.
:::

## Game kinds

| Value | Description |
| --- | --- |
| okey | Classic Okey for four players, one hand |
| okey101 | 101 Okey for four players, one hand, scored at its end |
| chess | Chess for two players, at positions 1 and 3 |
| dama | [Türk daması](#dama-moves) for two players, at positions 1 and 3 |
| dama_normal | [Normal dama](#dama-moves), Brazilian draughts on the dark squares, for two players at positions 1 and 3 |
| tavla | [Tavla](#tavla-turns), backgammon with no doubling cube, one game for two players at positions 1 and 3 |

## Game speeds

The player who opens a table chooses its speed.

| Value | Description |
| --- | --- |
| fast | 15 seconds a turn in okey, 25 in 101, and 20 in tavla, and 3 minutes a side in chess and both damas |
| normal | 30 seconds a turn in okey, 45 in 101, and 40 in tavla, and 10 minutes a side in chess and both damas |
| slow | 60 seconds a turn in okey, 90 in 101, and 90 in tavla, and 30 minutes a side in chess and both damas |

A chess or dama clock adds no increment.

## Table lifecycle

- [Open a table game](#open-a-table-game) puts the caller at position 1 of a lobby. Okey and 101 fill positions 1 to 4, and chess, both damas, and tavla fill positions 1 and 3.
- The game starts as the last position is taken. The server shuffles and rolls with a cryptographic random source, and in chess, dama, and tavla it draws the position that plays white.
- A lobby that does not fill within 10 minutes ends as `canceled` with reason `abandoned`, and so does a lobby its last player leaves. Leaving a lobby, or leaving the voice channel while in one, only gives up the position.
- When a game ends, its players return to lounge seats, or stand when none is free.
- An ended table stays readable for 5 minutes, and a new table can be opened on its slot at once.
- An account plays at one open table at a time, in any channel.
- A table whose slot is no longer in the channel's room theme ends as `canceled` with reason `theme_changed` on the next move or tick at it.

Every change to a table raises its `version` by one and sends a [Table Game Update](/gateway/events/#table-game-update) Dispatch to its players and subscribed spectators.

## Turns and clocks

In okey and 101 the turn passes from position 1 through 4 and around again, and `deadline_at` is the moment the turn runs out. The server then plays the turn for the player: it draws from the pile when the turn has not drawn yet, and discards the tile the player received last, or another one when that tile is a joker or would carry a penalty. A player whose turn runs out twice in a row loses the game as `forfeit` with reason `timeouts`. Any move of the player's own resets that count.

In tavla each turn has its own time as well, and `deadline_at` is the moment it runs out. The server then plays `legal_moves[0]` for the player, and a player whose turn runs out twice in a row loses as `forfeit` with reason `timeouts`. Any move of the player's own resets that count. A turn that passes because the roll has no play neither counts nor resets it.

In chess and both damas each side has its own clock. The side whose clock reaches zero loses, with reason `timeout`, whatever is left on the board.

The server settles an expired clock by itself on a timer that runs every second. A player's client can also send a `tick` action, which settles whatever is due at once. A spectator cannot send one.

## Leaving and disconnects

- [Leave a table game](#leave-a-table-game) during a game loses it at once, as `forfeit` with reason `leave`.
- A player who leaves the voice channel during a game is reported with `connected` false. Coming back within 30 seconds clears the mark. Otherwise the game ends as `forfeit` with reason `disconnect`, after the server confirms once more that the player is gone.
- A player whose other connection is still in the channel is not disconnected.
- The server also checks the players of a running game against the voice channel every 60 seconds, and marks a missing player the same way.

## Watching

Anyone connected to the channel can watch a table they do not play at. [Watch a table game](#watch-a-table-game) subscribes the caller to the table's [Table Game Update](/gateway/events/#table-game-update) Dispatches while the table has fewer than 50 subscribed spectators. Past that, `subscribed` is false, and the caller polls [Get a table game](#get-a-table-game) with its `ETag` instead.

Watching also issues a watch ticket for 60 seconds, subscribed or not. While the ticket lasts, Get a table game needs no `connection_id`. After it expires, the request sends `connection_id` again, and one that passes the voice membership check issues a new ticket.

An account watches one table at a time, so watching a table stops watching the previous one. Leaving the voice channel stops watching its tables.

A [watch seat](/http-api/voice-seats/#watch-seats) beside a table is only a place to sit. Its holder watches through Watch a table game like anyone else, receives the public view with `rack` null, and has no other right at the table.

## Reading tables

A player reads their own table at any time. Anyone else reads a table with a watch ticket or a `connection_id`, and [List table games](#list-table-games) always needs the `connection_id`.

Both reads answer with an `ETag`, `Cache-Control: private, no-cache`, and `Vary: Authorization`, and a matching `If-None-Match` answers 304 with no body. A response can carry the caller's own rack, so no shared cache may keep it.

The `ETag` of a table follows its `version` and the caller's position, so a change of `spectator_count` alone answers 304. The `ETag` of the list covers the whole response. Treat both as opaque values.

## Tile tokens

A tile is a string from `t0` to `t105`. For a numbered tile `tN`, the color is `(N mod 52) div 13` and the number is `(N mod 13) + 1`, and every numbered face exists twice.

| Value | Description |
| --- | --- |
| t0 to t103 | A numbered tile |
| t104, t105 | The two false jokers |

The color values are these.

| Value | Description |
| --- | --- |
| 0 | Yellow |
| 1 | Blue |
| 2 | Black |
| 3 | Red |

The indicator decides the joker: the face of the indicator's color with the next number, where 1 follows 13. The two tiles of that face are jokers, and the false jokers stand for that face.

## Dama moves

Squares are named as in chess, `a1` to `h8`, and white starts on the low ranks and moves toward rank 8. White moves first in both damas. The two kinds differ in these rules.

| Rule | Türk daması (`dama`) | Normal dama (`dama_normal`) |
| --- | --- | --- |
| Board | All 64 squares, 16 men a side on ranks 2-3 and 6-7 | The 32 dark squares with a1 dark, 12 men a side on ranks 1-3 and 6-8 |
| Men move | One square forward or sideways | One square diagonally forward |
| Men capture | Forward or sideways | Diagonally, forward or backward |
| Kings | Fly any distance along ranks and files | Fly any distance along diagonals |
| Taken pieces | Leave the board at once, so their squares can be crossed again | Stay as blockers until the move ends, and none is jumped twice |
| Lone kings | One king against one king is a draw at once | Play goes on |

A `dama_move` names the whole move as `path`: the square the piece starts on, then every square it stops on, 2 to 17 squares. A plain move is two squares. A capture lists one landing square for each piece it takes, so a chain that takes three pieces is four squares in one request.

- Capturing is compulsory, and the move takes as many pieces as the most any capture on the board takes. Men and kings count the same.
- A king captures at a distance and lands on any empty square past the piece it takes.
- No piece turns back the way it came within a capture.
- A man that reaches the last rank during a capture goes on as a man, and becomes a king only when the move ends there.
- Routes from the same start to the same end that take the same pieces are one move. `legal_moves` lists one of them, and the server accepts any of them.

The server checks each leg of a path against the rules, not against the list. `legal_moves` holds at most 1024 paths, and a path a crowded position leaves off the list is still accepted.

A side left with no pieces, or with no legal move on its turn, loses. The game is drawn when the same position with the same side to move comes up three times since the last advance, or after 25 moves by each side with no advance. An advance is a capture or a man moving forward, so a sideways man move or any king move in Türk daması is not one.

## Tavla turns

Points are numbered 1 to 24 in one frame for both sides, in `points`, `tavla_move`, `last_moves`, and `legal_moves`. White moves from 24 down to 1 and bears off from its home, points 1 to 6. Black moves from 1 up to 24 and bears off from points 19 to 24. Each side starts with 15 checkers: white has two on point 24, five on 13, three on 8, and five on 6, and black mirrors that on points 1, 12, 17, and 19.

A checker entering from the bar on die `d` lands on point `25 - d` for white and on point `d` for black. `bar` is only ever a `from`, and `off` only ever a `to`.

The server rolls the dice itself, from a cryptographic random source, as each turn starts. There is no roll action, and no roll exists before its turn starts. At the start of the game the server rolls one die for each side, rerolling ties, and the side with the higher die starts with two fresh dice. `opening` shows that opening roll on the first turn only.

A `tavla_move` carries the whole turn in one request, 1 to 4 steps.

- Both dice are played when possible. When only one of them can be played, it is the larger one if either could be. Doubles give four steps, played as far as they go.
- A checker on the bar enters before any other checker moves.
- A lone checker that is hit goes to the bar.
- Bearing off needs all 15 of the side's checkers in its home. A die higher than the farthest checker takes that checker off, and a die that fits a checker exactly may still be played inside the home instead.
- The server checks the turn as a whole, so any order or split of a legal play is accepted, such as a 6-5 sent as `24/18 18/13` or as `24/19 19/13`.

`legal_moves` holds one string for each distinct board a turn can leave, at most 3060. A string is the steps as `from/to` joined by spaces, such as `bar/22 13/7` or `6/off`, farthest from the mover's home first: the bar, then points descending for white and ascending for black. `legal_moves[0]` is the play the server makes when the turn runs out.

When a roll has no play, the turn passes at once and the next player's dice are rolled in the same change. An empty `legal_moves` shows up only after more than 16 such passes in a row, and that turn then passes when it runs out, without counting a timeout.

The first side to bear off all 15 checkers wins with reason `bear_off`, and the result has `finish` `mars` when the loser bore off none. A resignation or a forfeit is never a mars.

## Table game action types

| Value | Description |
| --- | --- |
| tick | Settles whatever is due at the table, in any game, from a player only |
| draw | Draws a tile in okey from `pile` or `discard`, and in 101 from `pile` only |
| discard | Discards `tile` in okey or 101 |
| finish | Finishes an okey hand, throwing `tile` and showing the rest of the rack as `sets` |
| take_discard | Takes the previous position's newest discard in 101, and uses it at once in `open` or `add` |
| meld | Opens or adds to melds in 101, through `open` and `add` |
| move | Moves a chess piece from `from` to `to`, with `promotion` for a pawn reaching the last rank |
| dama_move | Plays a whole [dama move](#dama-moves) along `path`, every capture of a chain in one request |
| tavla_move | Plays a whole [tavla turn](#tavla-turns) as `moves` |
| resign | Resigns a chess, dama, or tavla game |

## Rule violation reasons

A move the rules refuse returns 400 `TABLE_GAME_RULE_VIOLATION`, and the [error response](/http-api/#error-response) adds a `reason` member from this closed set. The body names no tile.

| Value | Description |
| --- | --- |
| not_your_turn | It is another position's turn |
| wrong_phase | The action does not fit the phase of the turn |
| tile_not_in_rack | A named tile is not in the caller's rack |
| invalid_meld | A set, run, group, or pair is not valid |
| open_too_low | A 101 opening with runs and groups counts too few points |
| pairs_too_few | A 101 opening with pairs has too few pairs |
| take_unused | A discard taken in 101 is not used in the same action |
| not_opened | A 101 player who has not opened adds to a meld |
| cannot_add | A tile does not fit the meld it is added to, or adding is not allowed yet |
| illegal_move | The chess, dama, or tavla move is not legal |
| game_over | The game has already ended |
| unsupported_action | The game has no such action |
| must_finish_with_discard | A 101 meld would leave no tile to discard |

## Act at a table game

<RouteHeader method="POST" path="/v1/channels/{channel_id}/table-games/{slot}/actions" />

Applies a player's [action](#table-game-action-object) to the table and returns the caller's [table game view](#table-game-view-object). The server first settles whatever is due at the table, such as an expired turn, and then judges the action against the settled table.

### Path parameters

| Field | Type | Description |
| --- | --- | --- |
| channel_id | snowflake | The ID of the voice channel |
| slot | string | The table slot |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| version | integer | The table `version` the action was made against, ignored for `tick` |
| action | [table game action](#table-game-action-object) object | The action |

A `version` other than the table's current one returns 409, and the client reads the table again. When the clock ran out before the action arrived, the settled turn is written and the action is then refused, so a refused action can still change the table.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [table game view](#table-game-view-object) object | The action was applied |
| 400 | [error response](/http-api/#error-response) | The rules refuse the action, returned as `TABLE_GAME_RULE_VIOLATION` with a [reason](#rule-violation-reasons) |
| 404 | [error response](/http-api/#error-response) | The slot has no table, returned as `UNKNOWN_TABLE_GAME` |
| 409 | [error response](/http-api/#error-response) | The caller does not play at the table, which includes every spectator, as `TABLE_GAME_CONFLICT` |
| 409 | [error response](/http-api/#error-response) | The version is stale, or a move is sent to a lobby, returned as `TABLE_GAME_CONFLICT` |

The [common responses](#common-responses) also apply.

### Side effects

An action that changes the table sends a [Table Game Update](/gateway/events/#table-game-update) Dispatch to its players and subscribed spectators before the response.

### Rate limit

30 requests per 10 seconds for each authenticated user, channel ID, and table slot, on the `table_game:action::channel_id::slot` bucket.
