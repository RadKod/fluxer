# Game catalog

Version 1 contains 150 curated PC game identities for the Turkey/Azerbaijan product scope: 98 have researched Windows executable aliases and 52 require manual selection. This is an editorial selection, not a measured regional popularity ranking. Executable research was accessed on 2026-10-06; no real games were launched in this task.

`src/catalog.json` is the shared source for display names and desktop matching. Its contract is `{version: 1, games: [{id, name, exe, icon, icon_source}]}`. IDs are stable lowercase ASCII slugs. `exe` contains lowercase full filenames without paths, commands, regular expressions or arguments. An empty array deliberately provides no automatic detection rule. No process list or executable path is sent to a server.

Consumers import `catalogVersion`, `gameCatalog`, `getGameById` and `matchGameByExe` from `@fluxer/game_catalog/src/GameCatalog`. The desktop build can resolve this source through its existing TypeScript alias pattern; add its workspace dependency when a desktop consumer is introduced so the unused-dependency gate remains accurate. The application calls `getGameIconUrl(id, 64 | 128)` from its game-activity URL helper only when displaying an icon; a null result uses the generic fallback.

Only reviewed game binaries are included. Launcher, patcher, anti-cheat, crash reporter, editor and generic Java/game filenames are excluded. Some metadata identifies only a wrapper or URI; those entries remain manual. Hell Let Loose matches only its Shipping game binary, and Sea of Thieves matches the publisher-documented Athena game binary rather than the root bootstrap. Hogwarts Legacy uses the same basename for bootstrap and game; the actual game binary is corroborated by its [depot](https://steamdb.info/depot/990081/). The Path of Exile versions both remain manual because their Steam launch basename collides. ARK: Survival Ascended uses only its distinct `arkascended.exe`; the legacy game's `shootergame.exe` is excluded from Ascended. Java Edition stays manual; Bedrock uses `minecraft.windows.exe`.

These are basename identity hints, not authenticated proof that a game is being played. Regional clients, updates, alternate editions and builds may use different binaries. A name match cannot distinguish dedicated servers or other applications using the same filename. Rules need maintenance when publishers rename processes; the future desktop integration must preserve the documented manual fallback.

## Provenance and rights

Names were cross-checked against 136 official Steam store `appdetails` responses and publisher product pages/search-indexed publisher titles for the 14 non-Steam entries (links below). Several publisher pages require JavaScript or failed direct retrieval; name evidence is not executable evidence. Display names omit trademark symbols and may use familiar short names. No Discord detectable list, CDN asset or old sanalyer code was used.

The two upstream factual rules come from [Fluxer detectables at ac1738dcde92eca5df0c6343cf0b8d1ab9cb13b2](https://github.com/fluxerapp/detectables/tree/ac1738dcde92eca5df0c6343cf0b8d1ab9cb13b2). Its [LICENSE](https://github.com/fluxerapp/detectables/blob/ac1738dcde92eca5df0c6343cf0b8d1ab9cb13b2/LICENSE) dedicates factual application mappings to CC0-1.0; schema/documentation are Apache-2.0, and images remain their owners' property. Only the Bedrock and osu! filename facts were reused; upstream schema, code and images were not copied. Minecraft Java's argument-dependent upstream rule is intentionally unsupported.

Steam launch evidence is Valve-origin `app_info` metadata accessed through **third-party** [steamcmd.net](https://api.steamcmd.net/v1/info/730), not a publisher-direct request. SteamDB configuration/depot pages are also third-party mirrors of Valve metadata. They are identified as mirrors, not official publisher documentation. Publisher support is preferred where available. Metadata was reviewed per game; it was not blindly imported as a process list. PCGamingWiki pages tested for CS2 and Dota 2 returned HTTP 403, so they supplied no rules.

For reproducibility, the table includes SHA-256 hashes for the captured raw Steam launch JSON where available. Raw store and launch responses, URLs, and detailed review notes are retained in the task's temporary `data/` evidence directory; they are not runtime dependencies. No API key or network call is required when consuming the shipped catalog. Hashes cover the observed snapshot and do not claim that the mirror is immutable or publisher-authenticated.

Game icons are separate publisher/store visual assets, not covered by the CC0 facts. A non-null `icon` identifies a local asset base; `icon_source` records its exact source URL and access date. The application serves local 64/128px WebP assets through its existing build asset pipeline. Null means use the existing generic fallback. The user's accepted icon copyright risk does not make these images CC0 or establish a redistribution licence. No remote URL from this metadata is loaded by the UI.

## Updating data

Retain IDs when names change. Research the actual Windows game process, exclude launchers and generic runtimes, resolve collisions, and record the source/date before adding an alias. Run the package catalog tests after edits. Icons require source metadata plus matching local 64/128px assets; executable metadata must remain usable independently of icon loading.

## Official icon assets

All 150 games have their own official game icon or logo in `fluxer_app/src/assets/images/games/`: one 64×64 and one 128×128 WebP per catalog ID. The 300 decoded files total **1,513,558 bytes** (about 1.44 MiB); the largest is **12,228 bytes**, below the 12 KiB per-file limit. There are **218 lossless** and **82 quality-85** files. Both dimensions and file size were checked after decoding every WebP with Pillow 12.2.0.

Sources were downloaded on **2026-10-06 (Asia/Baku)**. The catalog records each exact successful download URL and date. The icon assets remain third-party game artwork; the module's AGPL SPDX header applies to source code, not to the artwork's ownership. The user accepted icon copyright risk in the feature plan.

The 136 Steam game identities were checked with the official `IStoreBrowseService/GetItems/v1/` response. For 107 games, the exact `common.clienticon` hash from captured Steam appinfo metadata is downloaded as an ICO from the official Steam CDN; 102 of these provide at least a 128×128 frame. The captured appinfo metadata was obtained through the SteamCMD public metadata mirror, while the artwork download URL is Steam's own CDN. The remaining 29 Steam games use the official browse response's `assets.community_icon` hash and corresponding Steam CDN image. The remaining 14 games use the official publisher website, Riot press page, or Epic Games Store image link. No Discord, upstream detectables, fan-site artwork, exe extraction, or generated logo was used.

Images are resized with Lanczos. League of Legends, Fortnite, Wolfteam, Zula, and Point Blank use their official rectangular logo contained in a transparent square, without cropping or drawing new artwork. Existing transparency is preserved. Java and Bedrock use the same official Minecraft Creeper game mark.

**Source-detail limitation:** 36 square source icons are smaller than 128 pixels: 29 Steam games and World of Warcraft are 32×32; GTA IV and Factorio are 48×48; Fall Guys, Assetto Corsa Competizione and Hearthstone are 64×64; Stellaris is 96×96. These are upscaled outputs, not native 128-pixel artwork. Zula's 107×41 logo is also upscaled to fit the output. Insurgency: Sandstorm's larger official ICO exceeded 12 KiB at quality 85 in two attempts (largest frame and native 128 frame), so its smaller official icon was retained. Other 32-pixel Steam exceptions had no larger available client icon or lacked the client-icon metadata. The catalog's requested output dimensions do not imply restored source detail; no enhancement or synthesis was applied.

The static imports and URL table live in `GameIconAssets.ts`; the app wrapper loads this module dynamically. The bundler handles WebP as asset/resource URLs. Importing the shared catalog does not itself download images. The final app bundle must separately verify that the icon module is excluded from the initial entry chunk.

Local acquisition evidence: `icons/icon-results.json` records source page, exact download URL/date, original dimensions, transformation, raw source SHA-256/byte size, encoded byte size/quality, and output SHA-256. `icons/store-browse-{0,50,100}.json` and matching `.url` files preserve Steam metadata provenance. `icons/clienticon-probes.json` records which larger Steam icons were available and accepted. `icons/missing.json` is empty.
